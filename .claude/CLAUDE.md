## Commands

This project uses **Bun** (not npm/yarn — `package-lock.json` is gitignored).

```bash
bun install          # install dependencies
bun run dev          # start dev server at localhost:5173
bun run build        # type-check (vue-tsc) then Vite build → dist/
bun run preview      # serve the dist/ build locally
bun run type-check   # vue-tsc --noEmit only
bun run lint         # ESLint with auto-fix
bun run format       # Prettier on src/
```

There are no tests. CI (`.github/workflows/deploy.yml`) runs `type-check` then `build` on push to `main`, then deploys to GitHub Pages via `peaceiris/actions-gh-pages`.

## Architecture

Vue 3 SPA (Composition API + `<script setup>`) built with Vite, styled with Tailwind CSS, state via Pinia, routing via Vue Router 4. The `@` import alias maps to `src/`.

**Pages / routes** (all lazy-loaded; `router/index.ts` also sets `document.title` per route)
- `/` → `HomeView` — single-page portfolio: Hero → About → Skills → Experience → Projects → Testimonials → Contact, each as a section component under `src/components/sections/`.
- `/blog` → `BlogView` — lists posts.
- `/blog/:slug` → `BlogPostView` — renders a post with a table of contents and reading progress bar.
- `/:pathMatch` → `NotFoundView`.

**Site content is hardcoded in components.** The portfolio data (bio, experience entries, skills, projects, testimonials) is real profile data defined as typed arrays/objects inside each section component's `<script setup>`. To change site content, edit the relevant section component — there is no CMS or separate data layer.

**Blog content pipeline**
Posts live as Markdown files in `src/content/posts/*.md`; the filename is the slug. Frontmatter (parsed with `gray-matter`): `title`, `date`, `tags`, `description`, `cover_image`, `draft`, `featured`. `usePosts.ts` loads them at build time via `import.meta.glob(..., { query: '?raw' })` and renders Markdown with `marked` + `highlight.js`. The `marked` renderer is customised to add syntax-highlighted code blocks with a copy button, and anchor-linked headings (ids generated by `headingId()` — the same function feeds the table of contents). Draft posts (`draft: true`) are excluded. Featured posts sort first, then by date descending.

**Composables**
- `useActiveSection` — IntersectionObserver that tracks which section id is visible; used by NavBar to highlight the active nav link.
- `useReadingProgress` — scroll-based reading progress bar for blog posts.
- `usePosts` — `getPosts` / `getPost` plus the post/frontmatter types.

**Stores**
- `theme` — dark/light toggle; defaults to `prefers-color-scheme`, persisted in `localStorage`, applied as `.dark` class on `<html>`.
- `app` — loading flag and a notification queue (`notifySuccess/Error/Warning/Info`).

**Styling conventions**
Dark mode is class-based (`darkMode: 'class'`). A custom `primary` palette (indigo) is defined in `tailwind.config.js`. Reusable design-system classes live in `src/assets/styles/main.css` under `@layer components` — use these instead of re-composing utilities: `.btn-primary/.btn-secondary/.btn-ghost`, `.card`, `.section`, `.section-container`, `.section-heading`, `.section-subheading`, `.tag-primary/.tag-slate`, and `.prose-custom` (blog typography via `@tailwindcss/typography`).

**Home-page stage constraints**
The home page renders sections as full-viewport slides inside a transformed/scrolled compositing stack where CSS filters and layout-property animations produce rendering artifacts. Before adding glows, blurs, or animated effects to home-page sections or the NavBar, read `.claude/skills/stage-safe-visual-effects/SKILL.md`.

**Deployment / base path**
`VITE_BASE_PATH` controls the Vite `base` option. `.env.production` sets it to `/personal-website/` for GitHub Pages. If a custom domain is added, change that file to `/` (and set `cname` in the deploy workflow). The `public/404.html` handles SPA routing on GitHub Pages.
